## Pre-Build Findings

1. **Current canonical APEX version:** 69.10.13, from `config/apex_release_manifest.json`, with matching canonical capability-registry release identity.
2. **Current gamma snapshot schema:** existing `gamma_observational_snapshots` stored row ID, ticker, observation/source time, source/path version, net GEX, flip, 0DTE/0–1DTE/weekly shares, durability, capacity ratio, and `snapshot_json`.
3. **Current gamma snapshot identity:** no deterministic canonical gamma identity existed; identity was effectively row/time based.
4. **Existing gamma deduplication:** no canonical deduplication; observations used unconditional insert behavior.
5. **Current gamma-to-decision linkage:** decisions could contain gamma regime/path context but had no exact immutable canonical gamma snapshot reference.
6. **Current gamma-to-trigger linkage:** canonical trigger rows linked decisions but did not carry an exact gamma snapshot ID.
7. **Current gamma-to-grading linkage:** outcome grading used frozen decision rows/prices but did not have an explicit canonical gamma linkage contract proving decision-time gamma identity.
8. **Existing canonical feature sample identity:** already implemented and used as the architectural precedent; 69.10.14 does not create a parallel identity framework.
9. **Existing snapshot freshness:** transition staleness existed for historical windows, but there was no persisted decision-time gamma freshness state/age contract.
10. **Existing provider continuity:** no explicit canonical observation continuity/recovery/out-of-order state was persisted for gamma evidence.
11. **Existing immutable evidence/archive behavior:** decision evidence, payload compaction, immutable archive projection, and shadow validation already existed and were reused rather than replaced.
12. **Existing gamma retention policy:** no active storage-maintenance prune path targets `gamma_observational_snapshots`; this build preserves that behavior so new references are not orphaned.
13. **Existing gamma indexes:** `idx_gamma_obs_ticker_time(ticker, observed_at)` was the principal gamma observational index.
14. **Existing maturity/durability/transition fields:** 0DTE, 0–1DTE, <=7DTE concentration, structure durability, signed maturity rows where provider-derived, and 1m/5m/15m/30m transition context already existed.
15. **Overlap with specification:** gamma structure, capacity, durability, maturity concentration, transition dynamics, evidence eligibility, canonical feature samples, decision persistence, trigger observatory, grading, excursion capture, calibration, storage governance, immutable archive, scanner authority, and shadow validation already existed. They were extended rather than rebuilt.

### Provider provenance finding

The current QuantData Exposure By Strike parser does not expose a provider observation ID or provider-origin timestamp. `gamma_path.source_snapshot_at` is generated by APEX at parse time. 69.10.14 therefore preserves it for compatibility while labeling it `APEX_DERIVED_PARSE_TIME`; it is not claimed as provider-supplied time.

## Canonical Identity

Identity schema: `apex.gamma_snapshot_identity.v1`.

Canonical hash inputs are:

- ticker
- source
- provider observation ID when available
- provider source timestamp when available
- APEX observation timestamp only when provider observation ID/time are both unavailable
- path version
- level version
- gamma regime
- net GEX
- net gamma ratio
- GEX score
- gamma flip
- 0DTE share
- 0–1DTE share
- weekly gamma share
- durability
- snapshot capacity ratio when present
- term alignment/divergence only when signed maturity structure is actually available

Stable decimal normalization and sorted canonical JSON prevent identity drift from JSON ordering, insertion order, whitespace, process restart, or normal floating-point serialization noise.

Because QuantData currently provides neither an explicit observation ID nor a provider timestamp through this parser, unchanged values from separate polls are conservatively treated as separate observations via the APEX observation-time fallback. Exact replay/retry of one recorded observation still resolves to the same ID.

## Decision-Time Provenance

A finalized gamma-supported decision now freezes the exact canonical gamma snapshot reference and bounded evidence available at decision time.

The lifecycle explicitly refuses to query the newest gamma row when a historical decision lacks a snapshot ID. Legacy records therefore remain `LEGACY_OR_UNKNOWN` rather than receiving reconstructed contemporaneous evidence.

The frozen record includes age, freshness, continuity, provenance, regime, GEX, flip, maturity/durability, bounded transition lineage, and existing evidence eligibility. Existing gamma capacity/expected-move context is frozen only when the dynamic-state gamma reference matches the exact canonical snapshot ID.

## Historical Integrity

Later gamma observations cannot mutate the canonical gamma ID or frozen evidence associated with an already-persisted decision.

Outcome grading reads the frozen decision evidence and does not perform a latest-gamma lookup. Replayed, backfilled, and reconstructed evidence classes remain distinct from live-observed / decision-time-captured evidence.

Out-of-order observations cannot silently replace current live gamma authority.

## Storage Impact

Expected incremental storage is bounded to new scalar provenance columns, one short canonical ID, and bounded lineage/evidence metadata per unique observation/decision/trigger.

The build does **not** copy the full provider payload into each decision or trigger. Canonical deduplication also prevents duplicate rows for exact retries/replays of the same identified observation.

The existing storage-maintenance code does not prune `gamma_observational_snapshots`; 69.10.14 deliberately does not add a prune path that could orphan historical decision references. Future gamma pruning must preserve/archivally resolve referenced snapshots first.
