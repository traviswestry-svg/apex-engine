# APEX 69.10.14 — Canonical Gamma Evidence Identity & Decision-Time Provenance

## Purpose

APEX 69.10.14 closes the provenance gap between a gamma observation and the trigger, decision, historical evidence, outcome grading, and calibration records that rely on it.

The release establishes **evidence integrity, not predictive authority**. Canonical gamma identity does not create a trade, choose a direction, alter position sizing, bypass consensus, or grant execution authority.

## Canonical provenance chain

```text
Provider gamma response
  -> APEX gamma observation
  -> canonical_gamma_snapshot_id
  -> deduplication + temporal-integrity validation
  -> freshness + continuity + current-authority state
  -> existing gamma transition / maturity / durability intelligence
  -> existing evidence-eligibility gate
  -> canonical feature/decision composition
  -> frozen decision-time gamma evidence
  -> trigger + canonical decision linkage
  -> immutable historical decision record
  -> existing excursion / outcome grader
  -> calibration-ready evidence
```

## Canonical gamma snapshot identity

Identity schema: `apex.gamma_snapshot_identity.v1`

The deterministic identity is SHA-256 over canonical JSON and is stored as a bounded `g_<32 hex>` identifier. Numeric fields are normalized to stable decimal text before hashing; JSON key order, dictionary insertion order, binary floating-point artifacts, receive time, persist time, and process-generated UUIDs do not affect identity.

The canonical tuple is:

- identity schema version
- ticker
- source/provider path
- provider observation ID, when supplied
- provider source timestamp, when supplied
- APEX observation timestamp **only as an explicit fallback when the provider supplies neither observation ID nor source timestamp**
- gamma path version
- level/source-structure version
- gamma regime
- net GEX
- net gamma ratio
- GEX score
- active gamma flip / zero-gamma level
- 0DTE share
- 0–1DTE share
- weekly (<=7DTE) gamma share
- structure durability
- capacity ratio only when present in the snapshot input
- provider-grounded term alignment/divergence when signed maturity structure exists

### Why the observation-time fallback is required

The current QuantData Exposure By Strike parser does not expose a provider observation ID or a provider-origin timestamp. `gamma_path.source_snapshot_at` is generated by APEX during parsing. Therefore two unchanged provider polls cannot safely be assumed to represent one provider observation. In that case APEX observation time is explicitly part of identity, preventing false deduplication while preserving deterministic replay of the same recorded observation.

## Provider provenance truth

APEX now distinguishes:

- `provider_source_timestamp` — populated only when an explicitly provider/source timestamp is available.
- `source_timestamp` — retained for compatibility.
- `source_timestamp_provenance` — identifies whether the compatibility timestamp is `PROVIDER_SUPPLIED`, `APEX_DERIVED_PARSE_TIME`, or unavailable.
- `provider_observation_id` — populated only if one is actually supplied.

No provider metadata is fabricated.

## Indexes

- `idx_gamma_obs_ticker_time(ticker, observed_at)` — existing latest/history access pattern.
- `idx_gamma_obs_canonical_identity(canonical_gamma_snapshot_id)` — unique partial index for canonical lookup and deduplication.
- `idx_gamma_obs_session_time(session_date, ticker, observed_at)` — session/history inspection.
- `idx_gamma_obs_source_time(source, provider_source_timestamp)` — provider-time inspection when available.
- `idx_decisions_gamma_snapshot(canonical_gamma_snapshot_id, observed_at)` — decision linkage.
- `ix_trigger_gamma_snapshot_id(canonical_gamma_snapshot_id)` — trigger linkage.

`EXPLAIN QUERY PLAN` validation confirmed canonical gamma, decision, and trigger lookups use these indexes, while latest gamma lookup continues to use `idx_gamma_obs_ticker_time`.

## Deduplication and authority

Canonical inserts use `INSERT OR IGNORE` against the canonical-identity unique index. This safely deduplicates an exact replay/retry of one known observation.

Observations are not deduplicated merely because economic values happen to remain unchanged across distinct provider polls when provider observation identity/time is unavailable.

Out-of-order, replayed, backfilled, or reconstructed observations may be retained as useful historical evidence but cannot silently become the current live gamma authority.

## Freshness

Freshness is evaluated from provider source time when available; otherwise from the explicitly labeled APEX observation time.

States:

- `FRESH`
- `AGING`
- `STALE`
- `UNKNOWN`

A future-dated observation relative to the decision/reference time resolves `UNKNOWN` with invalid temporal order; it is never clamped to fresh.

Configuration:

- `APEX_GAMMA_FRESH_SECONDS` default `120`
- `APEX_GAMMA_AGING_SECONDS` default `300`
- `APEX_GAMMA_EXPECTED_CADENCE_SECONDS` default `60`
- `APEX_GAMMA_GAP_SECONDS` default `180`

QuantData Exposure By Strike may override each threshold with:

- `APEX_GAMMA_QUANTDATA_EXPOSURE_BY_STRIKE_FRESH_SECONDS`
- `APEX_GAMMA_QUANTDATA_EXPOSURE_BY_STRIKE_AGING_SECONDS`
- `APEX_GAMMA_QUANTDATA_EXPOSURE_BY_STRIKE_EXPECTED_CADENCE_SECONDS`
- `APEX_GAMMA_QUANTDATA_EXPOSURE_BY_STRIKE_GAP_SECONDS`

Closed-market aging is exposed as `PRIOR_SESSION_CONTEXT` rather than reported as a live-feed failure.

## Continuity and chronology

Continuity states are bounded and observational:

- `CONTINUOUS`
- `GAPPED`
- `RECOVERED`
- `BACKFILLED`
- `UNKNOWN`

Out-of-order observations carry explicit sequence state and do not replace the newest valid current-authority snapshot.

Malformed explicit timestamps fail closed; APEX does not silently replace malformed provider/observation time with `now`.

## Decision-time provenance

`engine.historical_evidence_lifecycle` now freezes the exact canonical gamma snapshot referenced by the finalized composition.

If no canonical gamma ID is present, the historical record resolves to `LEGACY_OR_UNKNOWN`. It does **not** query the latest gamma snapshot to fill the gap.

Frozen bounded evidence includes, when available:

- canonical gamma snapshot ID
- observation / receive / provider-source time
- timestamp provenance
- gamma source
- age at decision
- freshness
- continuity / sequence state
- provenance class
- gamma regime
- net GEX
- gamma flip
- maturity concentration
- durability
- term-structure availability/alignment/divergence
- bounded transition state/lineage
- existing dealer evidence-eligibility state
- existing gamma capacity state/ratio and expected move, **only when the decision-time dynamic-state gamma reference matches the exact canonical snapshot ID**

Gamma capacity remains correctly classified as an APEX decision-time derivation, not provider-supplied snapshot metadata.

## Decision storage

The existing `decisions` table adds:

- `canonical_gamma_snapshot_id TEXT`
- `gamma_snapshot_age_seconds REAL`
- `gamma_provenance_class TEXT`

The bounded `snapshot_json` also retains the frozen `gamma_evidence` object. Hard payload projection preserves the canonical reference and bounded gamma evidence instead of duplicating the provider payload.

## Trigger storage

The existing `observed_trade_triggers` table adds:

- `canonical_gamma_snapshot_id TEXT`

Canonical trigger capture reuses the historical decision capture / finalized gamma-transition reference. Trigger history and trade-view surfaces expose the reference without introducing a second gamma evidence store.

## Outcome grading integrity

The existing grader reads only the canonical decision row and its frozen gamma evidence. It does not query the latest gamma state while grading a historical decision.

Graded outcome JSON carries the frozen gamma provenance, including `latest_gamma_lookup_performed: false`.

Legacy records without linkage remain `LEGACY_OR_UNKNOWN`; reconstructed evidence is not silently represented as decision-time observed evidence.

## Term-regime divergence

Term-regime divergence is provider-gated. It is considered available only when signed maturity-bucket gamma ratios are actually present in the provider-derived term structure.

Concentration percentages alone never create signed maturity regimes.

## Decay pressure

No new categorical gamma-decay-pressure authority was introduced. Existing maturity concentration, durability, session-time, and transition measurements remain available for future calibration. This avoids inventing categorical thresholds before evidence supports them.

## Evidence eligibility

The existing dealer evidence-eligibility engine remains authoritative.

When canonical integrity is available:

- fresh + continuous evidence follows the existing path.
- aging evidence may be discounted.
- stale/gapped/replayed/backfilled/reconstructed evidence is contextual rather than treated as normal full-integrity evidence.
- unknown integrity fails closed for integrity-dependent gamma evidence.

Legacy records that do not have the new canonical integrity contract retain their pre-existing behavior rather than being retroactively reclassified.

## Storage and retention

No new unbounded high-frequency payload stream was added.

Storage follows the pattern:

```text
one canonical gamma snapshot
  + lightweight decision reference
  + lightweight trigger reference
  + bounded frozen decision-time evidence
```

The current APEX maintenance code does not automatically prune `gamma_observational_snapshots`, so 69.10.14 does not introduce a new prune path that could orphan historical references. Existing archive/compaction logic continues to govern the payloads it already owns. Any future gamma retention policy must archive or otherwise preserve referenced canonical snapshots before deletion.

## Observability

Bounded runtime counters expose:

- gamma snapshots received
- gamma snapshots created
- gamma snapshots deduplicated
- stale events
- gap events
- out-of-order events
- decisions linked
- decisions missing linkage
- reconstructed evidence events

IDs are never telemetry labels, preventing high-cardinality metric growth.

## API / dashboard surfaces

No new route family was created.

Existing surfaces now carry provenance fields where the underlying data is available:

- `/api/dynamic-state` — current gamma transition integrity and bounded provenance metrics.
- `/api/learning/evidence-lifecycle` — canonical decision/linkage readiness counts.
- `/api/triggers/history` — trigger-level canonical gamma reference.
- `/api/triggers/trade-view` — trigger detail with canonical gamma reference.

## Calibration readiness

69.10.14 enables leakage-safe future analysis of:

- alert/outcome quality by gamma age
- continuous vs gapped evidence
- durability conditioned on freshness
- transition reliability conditioned on evidence age
- maturity concentration by session phase
- post-alert gamma-state change
- useful lifetime of a gamma observation
- MAE/MFE by freshness/provenance class
- missing-linkage frequency
- capacity performance linked to the exact gamma snapshot used by the decision

No finding is automatically promoted into trading authority.

## Behavioral authority

**NO NEW DIRECT TRADING AUTHORITY.**

The release does not independently create BUY/SELL, CALL/PUT, direction, sizing, execution, or trade calls. Integrity state can influence gamma evidence only through the existing evidence-eligibility governance path.
